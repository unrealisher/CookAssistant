# CookAssistant

Личная коллекция рецептов: адаптивный сайт на React и TypeScript с API на FastAPI. В репозитории
подготовлены основа проекта, CI, локальная база и API личного аккаунта.

## Требования

- Python 3.12 или новее
- Node.js 24 или новее
- pnpm 11

Установите pnpm, если его ещё нет:

```powershell
npm install --global pnpm@11
```

## Запуск для разработки

Откройте два терминала в корне проекта. Один раз подготовьте окружение Python:

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
cd ..
```

В первом терминале запускайте API одной командой:

```powershell
.\backend\run.ps1
```

API автоматически перезапускается после изменения Python-файлов в `backend`.

Во втором установите зависимости сайта и запустите Vite:

```powershell
cd frontend
pnpm install
pnpm dev
```

Откройте адрес, напечатанный Vite (обычно `http://localhost:5173`). Vite проксирует `/api` на FastAPI.
Документация API доступна по адресу `http://localhost:8000/docs`, проверка здоровья —
`http://localhost:8000/api/v1/health`.

Для остановки каждого сервера нажмите `Ctrl+C` в его терминале.

## Локальный запуск на Windows

Для обычного использования соберите production-версию сайта и запустите один сервер:

```powershell
.\scripts\build.ps1
.\scripts\start.ps1
```

Оставьте окно PowerShell с сервером открытым. На том же компьютере сайт доступен по адресу
`http://localhost:8000`. Чтобы открыть его на телефоне, подключите телефон к домашней Wi‑Fi сети и
перейдите по адресу `http://<локальный-IP-компьютера>:8000` — IP-адрес можно посмотреть командой
`ipconfig`. Разрешайте доступ через брандмауэр Windows только для частной домашней сети. Не
настраивайте перенаправление порта роутера и не публикуйте этот HTTP-сервис в интернете. Для доступа
извне сначала настройте HTTPS через обратный прокси на личном сервере.

Перед выпуском проверьте цепочку миграций на отдельной временной базе:

```powershell
.\scripts\verify-migrations.ps1
```

Скрипт проверяет миграции Alembic на временной SQLite-базе и не изменяет рабочие данные. При обычном
обновлении `scripts/update.ps1` сначала сохраняет резервную копию, а затем запускает новую версию;
FastAPI применяет миграции к рабочей базе при старте.

Перед обновлением остановите сервер клавишами `Ctrl+C` и выполните:

```powershell
.\scripts\update.ps1
```

Скрипт обновления сохраняет резервную копию, получает актуальный `master`, пересобирает сайт и запускает
сервер. Оставьте окно PowerShell открытым; остановить сервер можно через `Ctrl+C`. Перед запуском
проверьте, что вы на ветке `master` и в рабочем дереве нет локальных изменений. API применяет
необходимые миграции при старте. Если обновление или миграция завершились ошибкой, не удаляйте
резервную копию.

## Резервные копии и восстановление

Создайте резервную копию командой:

```powershell
.\scripts\backup.ps1
```

По умолчанию копия сохраняется рядом с локальными данными CookAssistant вне репозитория; скрипт
выводит путь к созданному файлу. Для восстановления сначала остановите сервер, затем укажите файл
резервной копии явно:

```powershell
.\scripts\restore.ps1 -BackupPath "C:\путь\к\резервной-копии.sqlite3"
```

Восстановление заменяет текущую базу. Убедитесь, что выбрали нужную копию, и не запускайте сервер до
окончания восстановления. Перед обновлением или переносом храните копию отдельно от рабочей базы.

## Перенос на личный сервер

Переносите приложение только на сервер, которому доверяете. Перед переносом:

1. Остановите приложение и создайте резервную копию через `scripts/backup.ps1`.
2. Скопируйте репозиторий и файл базы на сервер по защищённому каналу. Не копируйте базу внутрь
   репозитория.
3. Настройте на сервере `COOKASSISTANT_DATA_DIR` на постоянный каталог вне checkout и поместите туда
   базу данных `cookassistant.sqlite3` до первого запуска API. Каталог должен сохраняться при
   обновлении приложения и перезапуске сервера.
4. Передайте `OPENROUTER_API_KEY` через менеджер секретов сервера или защищённую переменную окружения;
   не добавляйте ключ в Git и не публикуйте `.env`. При необходимости задайте
   `COOKASSISTANT_OPENROUTER_MODEL`.
5. Установите поддерживаемую версию Python и backend-зависимости. Для сборки сайта также нужны Node.js
   и pnpm; готовую frontend-сборку можно перенести вместе с приложением.
6. Запустите API в соответствии с операционной системой сервера и проверьте `/api/v1/health`. При
   старте FastAPI автоматически применит новые миграции. Перед каждым обновлением сначала создавайте
   и проверяйте резервную копию.

PowerShell-скрипты `scripts/*.ps1` предназначены для Windows и не настраивают службу Linux. Для Linux
или другого серверного окружения отдельно настройте запуск приложения и обратный прокси с HTTPS.
Ограничьте доступ к серверу домашней сетью; открывайте доступ извне только через HTTPS.

## Аккаунт и API

При первом запуске API применяет миграции SQLite. База и локальные настройки хранятся в каталоге
данных вне репозитория; путь можно задать через `COOKASSISTANT_DATA_DIR`.

Перед входом создайте единственный аккаунт владельца. Узнать, требуется ли настройка, можно запросом
`GET /api/v1/auth/status`. Для создания отправьте `POST /api/v1/auth/setup` с JSON:

```json
{
  "username": "owner",
  "password": "at-least-12-characters"
}
```

Установка аккаунта автоматически начинает сессию в браузере. После выхода используйте
`POST /api/v1/auth/login` с теми же полями; `POST /api/v1/auth/logout` завершает текущую сессию.
Повторно создать аккаунт через API нельзя. Запросы рецептов требуют активную сессию:

- `GET /api/v1/recipes` — список; параметр `q` ищет по названию и тегам.
- `POST /api/v1/recipes` — создать структурированный рецепт.
- `GET /api/v1/recipes/{id}` — открыть рецепт.
- `PATCH /api/v1/recipes/{id}` — изменить переданные поля.
- `DELETE /api/v1/recipes/{id}` — удалить рецепт.

Схемы запросов и ответов опубликованы в OpenAPI: `http://localhost:8000/docs`.

После запуска откройте адрес Vite. При первом входе сайт предложит создать аккаунт владельца,
затем откроет личную коллекцию. Рецепты можно добавлять вручную, искать по названию и тегам,
открывать, изменять и удалять. Поиск по ингредиентам не выполняется.

При создании вставьте или надиктуйте свободный текст рецепта и нажмите «Сохранить рецепт». API
отправит текст модели через OpenRouter Responses API и сохранит исходный текст вместе с разобранными
ингредиентами, шагами, временем, температурой и тегами. После сохранения рецепт можно целиком
исправить вручную.

Для ИИ-разбора скопируйте .env.example в .env в корне репозитория и укажите OPENROUTER_API_KEY.
Ключ используется только backend-сервером и не попадает в сайт. При необходимости модель можно
сменить через COOKASSISTANT_OPENROUTER_MODEL; по умолчанию используется openai/gpt-4o-mini.
OpenRouter предоставляет доступ к моделям разных поставщиков через единый API; стоимость зависит
от выбранной модели. Если виртуальное окружение уже создано, установите в него актуальные backend-
зависимости из каталога backend командой `python -m pip install -e ".[dev]"`. Тесты подменяют
запрос и не делают платных обращений к API.

## Проверки

Backend:

```powershell
cd backend
python -m ruff check .
python -m ruff format --check .
python -m pytest
```

Frontend:

```powershell
cd frontend
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

GitHub Actions запускает эти проверки при открытии или обновлении pull request и при push в `master`.
